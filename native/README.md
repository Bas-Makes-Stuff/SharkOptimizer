# Native SharkOptimizer

## Automatic Game Boost (2.0.2 candidate)

Saved profiles can opt into external-launch detection while the app runs, including in the tray. Detection runs on a worker every three seconds and matches full detected executable paths. One session runs at a time; manually ending a session suppresses that game until it exits. A fifteen-second absence grace allows short process handoffs. Inaccessible process paths stay uncertain rather than triggering restoration.

Saving an automatic profile shows its actions for approval. Closing selected apps requires a separate opt-in; lowering priority uses the existing saved recovery engine. Game exit restores temporary settings and saves the recap. Tray recap notifications open Recent sessions. Backup imports disable automatic actions until the user enables them again.

`checks/AutomaticGameBoost.Check.ps1` verifies disabled defaults, exact-path matching, an externally launched fixture, duplicate prevention, real isolated-process priority restoration, manual-stop suppression, grace timing, recap history and profile serialization. It uses preview app state and no Windows policy changes. Actual games, anti-cheat path access and the notification click still need user verification.

This is the side-by-side C# / WPF rewrite for version 2.0.2. It builds as a Windows executable with the .NET Framework C# compiler already present on Windows. The application itself does not use PowerShell and requests administrator access, matching the current installer.

The user requested an EXE refresh after the behavior-preference feature. The following batch is now compiled into the normal native executable. Focused checks cover backup round-trips, loaded session profiles, isolated-process priority recovery, service-state fixtures, report bounds, median handling, actual memory sampling, startup XML, and rendered page layouts:

- Game Boost Windows Update service pause/resume, optional working-set trimming, and 50 persistent session reports, with asynchronous service waits and interrupted-session recovery.
- Per-account tray startup registered by installation, a `--tray` launch mode, Settings enable/disable controls, and a single-instance shortcut signal. Installation enables startup; updates preserve an existing disabled preference, and uninstall removes the current account's task.
- Dashboard CPU/RAM/GPU readings while visible, with background sampling and missing-data states. Sampling stops when the Dashboard is hidden or the app is in the tray.
- A 60-run benchmark history, median comparisons using the latest three BEFORE/AFTER samples, CSV export, bounded DNS waits, legacy history migration, and setup-backup integration. Process/service counts are context and do not imply a performance gain.

Installation, uninstall/reinstall, tray reopening, sign-in startup, CPU sampling, and first-launch/saved language behavior have been checked on the development PC. A complete newer-version GitHub update and live Windows Update service changes remain unverified. Service recovery checks use fixtures and do not stop the real Windows Update service. Missing GPU readings remain unavailable rather than being fabricated.

- App behavior preferences include completion notifications while hidden in the tray, activity-log visibility, background game scanning at startup, and reduced motion. Legacy notification/log/scan preferences migrate once and are included in setup backups. Reduced motion skips the splash and workspace-card movement. Game scans preserve existing saved paths and avoid overlapping scans. The collapsed activity log has text export and a bounded local file.
